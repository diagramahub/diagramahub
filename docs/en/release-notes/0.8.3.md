# 0.8.3 (2026-10-11)

Fix for the published documentation site: it is now built with MkDocs Material and deployed correctly to GitHub Pages. No code changes, no migrations and no new features.

## ⬆️ Upgrade notes

- No code changes or migrations; documentation and the site publishing pipeline only.
- The GitHub Pages configuration moves from "Deploy from a branch: main /docs" to "GitHub Actions".

## 📚 Documentation

- **The documentation site now looks the way it should.** GitHub Pages published the `docs/` folder with the default Jekyll theme: it showed raw Markdown with no navigation, no search, no theme and no language switcher, and `https://diagramahub.github.io/diagramahub/` returned 404 because there was no root page.
  - A GitHub Actions workflow (`.github/workflows/docs.yml`) now builds the site with MkDocs Material and publishes it to Pages. Added `site_url` (the site lives under the `/diagramahub/` subpath), a root landing page, the project logo and favicon, and the language switcher now points at the right URLs.
  - The UI on English pages is in English (search, table of contents, navigation): Material only supports one UI language per site, so a small theme override picks it per folder (`overrides/partials/language.html`).
  - `mkdocs build --strict` runs on every push and pull request, so a broken link fails the build instead of being published.
  - Fixed the two links in the 0.5.9 release notes that pointed outside the documentation directory.

## 🧪 Tests

- No test changes: this release touches neither backend nor frontend code.
