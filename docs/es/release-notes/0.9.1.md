# 0.9.1 (2026-11-22)

Versión de mantenimiento: la imagen del frontend pasa a nginx 1.31 y corrige los CVE de nginx que quedaron como problema conocido en 0.9.0, y pyotp se actualiza a 2.12.0. No trae funciones nuevas ni cambios visibles para el usuario.

## ⬆️ Notas de actualización

- Reconstruye las imágenes (`docker compose up -d --build`): cambió la imagen base del frontend y una dependencia del backend.
- No hay migraciones ni cambios de configuración. El MFA configurado sigue funcionando igual.

## 🔒 Seguridad

- **nginx 1.31 en la imagen del frontend.** La imagen base pasa de `nginxinc/nginx-unprivileged:1.30-alpine` a `1.31-alpine` (nginx 1.31.7). Con esto se corrigen CVE-2026-113425, CVE-2026-121810, CVE-2026-123007, CVE-2026-123633, CVE-2026-118899 y CVE-2026-123634, el problema conocido de [0.9.0](0.9.0.md). La imagen de 1.30.7 todavía no se publica; la serie 1.31 (*mainline*) es la que nginx recomienda. El escaneo de Trivy del CI (CRITICAL/HIGH con corrección disponible) vuelve a pasar sin hallazgos. La configuración de nginx no cambia.

## 🔧 Interno

- **pyotp 2.12.0.** Ahora exige secretos TOTP de al menos 112 bits e intervalos de 120 s como máximo. DiagramaHub genera secretos de 160 bits con intervalos de 30 s, así que el MFA de las cuentas existentes no cambia.
- Las actualizaciones mayores pendientes (SDK de Stripe 17, Tailwind CSS 4, Node 26, Python 3.15 y MongoDB 8.2) quedan para 0.10.0. El SDK de Stripe 17 requiere una migración: desde la v12, `current_period_end` está en los *items* de la suscripción y no en la suscripción.

## 🧪 Pruebas

- Backend: **766 pruebas**, cobertura **72,85 %** (piso 60 %), con pyotp 2.12.0. Imagen de producción del frontend: build correcto, Trivy sin hallazgos CRITICAL/HIGH y prueba de arranque (nginx 1.31.7 responde y aplica la CSP). El código del frontend no cambió.
